本期摘要

本期 OpenWrt 社区围绕 MT7621 老机型适配、升级回滚与 IPv6/DNS 代理故障展开讨论；Linux 侧关注 LWN 周报与 Julia 1.13，芯片领域则以 EDA、AI 芯片与传感器设计访谈为主。

Linux 动态

LWN.net 周报：C++26、Buildroot 与更快的 futex

本期 LWN 周报封面涵盖 C++26 标准进展、Buildroot 构建系统、futex 性能优化、终端工具 Zellij 及 Julia 语言；简讯部分涉及 NGINX RCE 漏洞、curl 三十周年、Rust 1.100 等。对关注内核与系统底层的读者，futex 优化是无线子系统之外值得留意的并发基础设施动向。

路由器 & OpenWrt

D-Link DIR-1960 A1 通过 D-Link Recovery GUI 安装 OpenWrt

DIR-1960 A1 搭载双核 MT7621 处理器，2.4 GHz 最高 600Mbps、5 GHz 最高 1300Mbps，双频合计 1900Mbps。Wiki 页面更新了使用 D-Link Recovery GUI 的安装流程，目前暂无实验性版本标注。MT7621 平台在 OpenWrt 生态中仍有稳定维护价值。

T-Com Speedport W724V Typ B 更新二进制下载链接

该机型由 Arcadyan 制造、德国电信分发，Wiki 页面仍处于建设中，本次更新了二进制文件链接。对持有该设备的用户而言，页面完善程度有限，刷机前需谨慎核对硬件版本。

Linksys MR6350 刷入 OpenWrt 25 并规划 VLAN 分段

社区用户反馈 MR6350 已成功刷入 OpenWrt 版本 25，并通过 5 GHz WiFi 连接 Starlink 正常上网。其下一步计划用 VLAN 将网络划分为 IoT、办公与游戏三类。该帖体现了消费级路由器在 OpenWrt 下做网络隔离的典型需求。

升级失败后如何通过 SSH 恢复备份

用户升级路由器固件前备份了可用固件，升级后无法进入 Web 界面但 SSH 仍可登录，询问如何回滚备份。帖子已有 4 帖、3 人参与讨论。此类问题凸显升级前保留备份与启用 SSH 恢复通道的重要性。

https-dns-proxy 在 IPv6 设为 auto 时启动失败并循环引导

用户报告 https-dns-proxy 在 IP 协议族设为自动（auto/双栈）时，守护进程在解析备用 DNS 的初始引导阶段持续失败，形成 bootstrap 循环。该问题与双栈环境下的解析顺序有关，值得使用加密 DNS 的 OpenWrt 用户排查配置。

🔗 原文

Ubiquiti UAP-AC-M 搭配 UMA-D 外置天线在 OpenWrt 下是否即插即用

用户询问 UAP-AC-M 接入 UMA-D 双频定向天线后，在 OpenWrt 下是否需要特殊设置。原厂 UniFi 固件需手动启用外置天线选项，否则不会生效，因此 OpenWrt 侧的天线配置方式成为关注点。该问题涉及外置天线与射频链路配置的兼容性。

编辑小结

本期 OpenWrt 侧以社区维护与故障排查为主：MT7621 老平台仍有 Wiki 更新，说明存量设备的生命周期被社区延续；升级回滚、双栈 DNS 引导循环、外置天线配置等问题则提醒用户，固件升级前的备份与协议族配置需谨慎对待。Linux 侧值得关注的是 futex 性能优化等底层基础设施进展，它们会间接影响路由转发与并发处理效率。芯片领域本期偏重 EDA 与架构访谈，缺少 WiFi 芯片的直接动态，建议读者持续跟踪 Qualcomm、MediaTek 后续在 WiFi 7/8 平台上的节奏。总体而言，本期更适合作为排障与存量设备维护的参考，而非标准演进的观察窗口。
