Linux 动态

AMD 为混合架构 CPU 提交容量感知调度补丁

AMD 上周末向 Linux 内核提交了一组驱动补丁，目标是让 Capacity Aware Scheduling 在 AMD 异构/混合处理器上生效。这意味着大小核混合设计的调度器可以更准确地按核心容量分配任务，对能效与响应延迟都有潜在收益。目前补丁仍处于评审阶段，尚未确认合入时间线。

路由器 & OpenWrt

wwand-ims：让 LAN 内 SIP 电话或 PBX 用上 VoLTE

wwand-ims 是 OpenWrt 上蜂窝模组连接管理器 wwand 的插件，可通过蜂窝数据模组发起 VoLTE 通话，并转交给 LAN 内的普通 SIP 电话或 PBX 中继。其特别之处在于：IMS UE 由路由器本身承担，而非模组。这对用蜂窝链路替代固定语音线路的场景颇具吸引力。

🔗 原文

TP-Link Archer AX80 v1 拆机信息更新

OpenWrt 硬件数据库（ToH）更新了 TP-Link Archer AX80 v1 的页面，新增拆机相关内容。该机型为双频 Wi-Fi 6（802.11ax）家用路由器，标称无线合并速率最高 6.0 Gbps，定位于高性能家庭或小型办公场景。拆机信息对评估其 OpenWrt 移植可行性与硬件做工有直接帮助。

🔗 原文

开启防火墙日志后出现延迟问题

有用户在 Fortinet FortiGate 50E 上运行 OpenWrt 25.12.6，发现只要启用任意日志功能就会出现延迟。起初怀疑是 ISP 问题，后在观察到指向网关的延迟尖峰后转向排查硬件，并已逐步缩小范围。该帖对在 x86/企业级硬件上跑 OpenWrt 并依赖防火墙日志的部署有参考意义。

用 acme.sh 从私有 CA 签发证书

用户拥有支持 ACME 的私有 CA，希望为 uhttpd 服务签发证书。但 luci-app-acme 基于 acme.sh，似乎只支持固定的外部 ACME 服务商列表，无法指向自建 CA，导致无法为 LuCI 提供证书。该讨论涉及 OpenWrt 上证书自动化与私有 PKI 的兼容性缺口。

🔗 原文

为 OpenWrt 引入 Zabbix Agent 2（8.0 LTS）

有用户在 Banana Pi BPI-R3（mediatek/filogic）上运行 OpenWrt 25.12.6，使用 zabbix-agentd 主动检查监控路由器，希望社区提供基于 Zabbix 8.0 LTS 的 zabbix-agent2 软件包。其 Unraid 服务器已使用 Agent 2，希望两端版本能力对齐。这反映了 OpenWrt 在企业监控体系中的定位正在增强。

编辑小结

本期最值得关注的是 wwand-ims 所代表的思路：把 IMS UE 从蜂窝模组上移到路由器，让 OpenWrt 设备直接成为语音网关，这可能为固网语音退网后的替代方案提供新选项。芯片侧，Nvidia 高层变动与 IEDM 2026 的议题共同说明，AI 算力竞赛正在向器件与能效层面下沉。OpenWrt 社区则持续在”企业级可用性”上补课，从 Zabbix Agent 2 到私有 CA 证书支持，都是运维向需求。建议读者对私有 CA 与防火墙日志性能两类问题保持关注，前者影响内网 TLS 部署，后者可能暴露转发路径上的隐性开销。硬件层面，Archer AX80 的拆机资料更新对评估 Wi-Fi 6 机型的 OpenWrt 移植价值有直接帮助。
