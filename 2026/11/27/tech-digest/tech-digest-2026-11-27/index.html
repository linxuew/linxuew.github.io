本期摘要

OpenWrt 社区集中更新多款 AVM FRITZ!Box、NETGEAR Orbi 与 Google Wifi 的设备页，同时 mt76x8 平台的 SMALL_FLASH SquashFS 启动性能被实测量化；无线侧 ISAC 与 AI-RAN 的商用节奏成为运营商关注焦点。

Linux 动态

周四安全更新汇总

AlmaLinux 发布新一轮安全更新，覆盖 kernel、openssl、nginx（1.24/1.26 分支）、firewalld、ghostscript、php 等组件。对企业级路由与网关设备而言，nginx 与 kernel 的更新值得优先关注。

AI Agent 技能文档或将进入 Linux 7.5

Phoronix 报道，面向 Linux 7.5 合并窗口，社区拟提交 in-tree 文档，用于指导 AI agent 理解不同内核流程。这反映内核开发流程正在主动适配 AI 辅助开发的新常态。

路由器 & OpenWrt

Google Wifi 设备页更新（LED 部分）

Google Wifi 为 2×2 802.11ac AP，采用四核 Qualcomm IPQ4019 SoC、512 MB RAM 与 4 GB eMMC。其原厂固件基于 ChromeOS，bootloader 为 Coreboot + Depthcharge，页面讨论如何让其运行非 Google 签名软件（如 OpenWrt）。

🔗 原文

AVM FRITZ!Box 7560 页面新建

FRITZ!Box 7560 是 VDSL/ADSL 路由，采用 Intel/Lantiq GRX350（PXB4395）SoC，256 MiB RAM、128 MiB NAND flash，含四个千兆口。页面标注仍在建设中，社区可参与补全。

🔗 原文

FRITZ!Box 7590 页面更新开发状态

FRITZ!Box 7590 搭载 Intel/Lantiq GRX550（PXB4583）SoC，512 MiB RAM 与 512 MiB NAND flash，同样具备四个千兆口。本次更新补充了当前开发进展。

🔗 原文

基准测试：SMALL_FLASH SquashFS 在 mt76x8 上增加 54 秒启动时间

在 TP-Link Archer C50 v4（ramips/mt76x8，580 MHz MT7628AN，64 MB RAM，8 MB SPI NOR）上，从内核启动到 Wi-Fi 就绪约需 96 秒，CPU sys 占用长期高于 80%，kworker/kblockd 贯穿全程。默认 SMALL_FLASH SquashFS（1024K × 2 槽位）被指为此增加约 54 秒。

🔗 原文

Cudy TR1200：5GHz STA 模式下自发重启

用户报告 TR1200 每日重启一两次，怀疑与 26.12.5 上的 MT7613BEN 驱动有关，在 2.4GHz 与 5GHz 同时使用、或 2.4GHz 作 BR-LAN 配有线 WAN 并启用 STA 时均有出现。此类驱动稳定性问题值得 MT76 平台用户留意。

🔗 原文

编辑小结

本期 OpenWrt 侧以设备资料维护为主，FRITZ!Box 系列与 NETGEAR Orbi 的 Techdata 持续被补全，说明社区对 x86 之外的 DSL 与 mesh 设备兴趣不减。mt76x8 的启动基准值得低闪存设备用户重视，SquashFS 槽位配置对启动时间的开销已被量化，选购或定制固件时应权衡。无线领域，ISAC 与 AI-RAN 的讨论表明 5G 后期与 6G 的边界正在模糊，运营商试验节奏加快。芯片侧则集中在 3D IC 与 EDA 工具链整合，短期对路由器硬件影响有限，但长期将改变封装与验证流程。建议关注 MT7613BEN 驱动的修复进展，以及小闪存设备启动优化的后续讨论。
