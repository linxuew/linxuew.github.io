无线与路由技术动态 2026-11-09

发表于2026-11-09|更新于2026-11-09|技术动态
|阅读量:

本期摘要

本周 OpenWrt 社区动作密集：25.12 分支的 SSH 组件切换与 apk 包管理器相关的 kmod 兼容问题成为讨论焦点，同时多款路由器入库或补充硬件数据。Linux 内核侧则继续推进 AMD Ryzen AI NPU 与 PerfOpt 性能优化。

Linux 动态

Linux 7.5 将扩展 AMD Ryzen AI NPU 的 AIE4 支持

Linux 7.4 合并窗口尚未结束，面向 7.5 的 drm-misc-next 拉取请求已出现第三批，其中包含更多 AMD Ryzen AI NPU 的 AIE4 启用代码。这表明 AMD 在端侧 AI 加速上的内核支持正在持续补强，对搭载 NPU 的移动与桌面平台意义较大。

🔗 原文

AMD PerfOpt 性能优化代码在 Linux 7.4-rc2 中调整

Linux 7.4 引入的 AMD PerfOpt 针对集成 Radeon 显卡的 SoC 提供开箱即用的性能提升，尤其在 AI/LLM 负载下对 iGPU 有明显增益。rc2 阶段相关代码经过微调，说明该特性正逐步趋于稳定。

🔗 原文

WiFi 标准 & 技术

Chainalysis 称黑客窃取全部客户的凭证与令牌

Chainalysis 披露一起“多线 cyberattack”，涉及 AI agent 参与以及 on-path 数据截取，导致其所有客户的凭证和令牌被窃。该事件虽非 WiFi 标准本身进展，但对无线网络安全实践与供应链信任具有警示意义。

🔗 原文

VMware 发布 vSphere Express，支持最多 128 核虚拟化

VMware 推出面向中小规模场景的 vSphere Express，最高支持 128 核。官方称此举源于对低端客户需求的重新倾听，反映出虚拟化产品线在边缘与中小部署场景的调整。

🔗 原文

Binance 称窃取数十亿美元加密货币的黑客筹划数月

Binance 表示相关攻击者通过笔记本感染、内部工具失陷以及虚假面试等手段长期布局。该案例再次说明企业网络边界与终端安全在无线接入普及背景下的重要性。

🔗 原文

UEFI bootkit 感染全补丁 Windows 设备，Secure Boot 保护受质疑

BlackX UEFI bootkit 利用 Microsoft 在 Secure Boot 保护机制上的模糊地带，感染了已完全打补丁的 Windows 机器。对于路由器与嵌入式设备固件安全而言，启动链信任问题同样值得关注。

🔗 原文

芯片 & 硬件

Finchetto CEO 访谈：全光网络交换面向 AI 与超大规模数据中心

Finchetto 专注全光网络交换技术，面向 AI 与 hyperscale 数据中心，重点在降低功耗。其 integrated photonics 路线若成熟，可能对数据中心内部互联的功耗与带宽瓶颈带来新解法。

🔗 原文

Kneron CEO 访谈：推动 Edge AI 与端侧推理

Kneron 创始人 Albert Liu 介绍了公司自 2015 年以来推动 on-device Edge AI 的使命，目标是把推理从集中式云端下沉到终端设备。这与 WiFi 路由器、智能网关逐步集成 AI 能力的趋势相呼应。

Amplio CEO 访谈：AI 驱动的工业资产回收

Amplio 利用 AI 帮助制造商从闲置设备与库存中回收价值，CEO Trey Closson 具备十余年全球物流与供应链经验。该方向体现了 AI 在工业供应链侧的落地，而非单纯的芯片设计话题。

🔗 原文

Addionics CEO 访谈：3D 集流体与电池创新

Addionics 创始人 Moshiel Biton 介绍公司在电池领域的创新，已融资超过 8500 万美元并建立 3D Current Collectors 制造设施。对无线与路由行业而言，属于配套电源与储能技术的间接参考。

🔗 原文

Electroninks CEO 访谈：材料科学与电子 prototyping

Electroninks 联合创始人 Brett Walker 介绍了公司在材料科学方面的积累，以及 Circuit Scribe 等电子原型产品。该内容偏向电子制造材料，与无线芯片直接关联有限。

路由器 & OpenWrt

OpenWrt 25.12：将 Dropbear 密钥转换为 OpenSSH 格式

在从 Dropbear 迁移到 OpenSSH 时，需用 dropbearconvert 转换主机密钥，否则已连接过的客户端会提示 host key 变更。OpenWrt 25.12 上这是一步简短的手动操作，升级前应提前处理。

🔗 原文

OpenWrt 25.12：用 OpenSSH + SFTP 替换 Dropbear

OpenWrt 默认使用精简的 Dropbear SSH 服务器，功能有所缺失；可改装体积更大但功能更全的 OpenSSH，这也是桌面发行版的默认选择。文档针对 25.12.x 做了更新，适合需要 SFTP 的用户参考。

🔗 原文

OpenWrt snapshot + apk：apk upgrade 安装了与运行内核不匹配的 kmod

有用户在 25.12/snapshot（E8450）上遇到 apk 升级后 kmod 与当前内核不匹配的问题，并将其与 2019 年 opkg 时代的“kmod 不同步”旧帖对照。包管理器切换后机制有所变化，该帖汇总了当前陷阱的具体表现。

🔗 原文

Cudy LT700 Outdoor v1 建立 stub 页面并录入硬件数据

OpenWrt ToH 新增 Cudy LT700 Outdoor v1 的 stub 页面，并同步创建了硬件数据条目。该设备属于户外型 LTE 路由，后续字段完善情况值得关注。

🔗 原文

Linksys EA8300 页面补充 EA8250 信息

Linksys EA8300 是一款 MU-MIMO 三频 WiFi 路由器，具备一个 2.4GHz 和两个 5GHz 接口。页面新增了 EA8250 的相关信息，并提醒升级到 22.03 以上版本需先安装 22.03 并调整 U-boot 参数。

🔗 原文

编辑小结

本期最值得动手实践的是 OpenWrt 25.12 的 SSH 组件迁移：若你计划从 Dropbear 切换到 OpenSSH，务必先用 dropbearconvert 保留主机密钥，避免客户端告警。apk 包管理器下的 kmod 与内核不匹配问题在 snapshot 上仍有复现，建议升级前确认内核与 kmod 版本对应，或暂缓在关键设备上跟进 snapshot。硬件侧，Cudy LT700 Outdoor 与 Linksys EA8250 的数据条目仍在完善中，购买或刷机前应先核对 ToH 字段。Linux 侧 AMD NPU 与 PerfOpt 的推进，预示着未来路由器与网关在端侧 AI 加速上的想象空间，但短期内对主流 OpenWrt 设备影响有限。
