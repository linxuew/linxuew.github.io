用户以 Fritzbox（192.168.1.1）为主路由，接 UGreen NAS（192.168.1.2，跑 Jellyfin 与 Minimserver 容器），另在客厅使用 CUDY X6 路由，询问跨网段访问的正确路由配置。属于典型的双 NAT/多子网排障场景。

QoS-Ex：面向游戏的 QoS 与游戏服务器 Ping 过滤器（OpenWrt 24.10 / 25.12）

QoS-Ex 是面向 OpenWrt 24.10 与 25.12 的游戏 QoS 套件，包含整形器（默认 CAKE）、可选的游戏服务器过滤器与 LuCI 应用，支持一键配置。项目在 GitHub 开源并提供最新 release。

用户将旧 iPhone 通过 USB 接到 GL.iNet Mango，希望以约 60 Mbit/s 共享蜂窝网络给局域网，询问需要何种级别的设备才不成为瓶颈。对低端 ARM 路由器的 USB 网络共享吞吐能力具有参考价值。

是否应在固件选择器中这样配置 WiFi

用户贴出一段 UCI 脚本，设置 radio0 与 default_radio0 启用、SSID、sae+ccmp 加密、密码与随机 MAC，询问是否可在 Firmware Selector 中以此预置 WiFi。涉及首次启动即生效的无线配置方式。

GCC 更新至 14.4.0 的讨论

GCC 14.3.0 存在 SVE 相关问题，已在 14.4.0 修复。社区询问 OpenWrt 25.12 是否有计划跟进升级工具链，关系到 ARM 平台编译与优化表现。

编辑小结

本期 OpenWrt 社区的热点集中在“可用性”而非新硬件：多子网路由、USB 网络共享性能、无线配置预置与工具链版本，都是部署与维护中的真实痛点，QoS-Ex 这类围绕 CAKE 的垂直场景套件值得关注。芯片侧的关键词是物理 AI 与平台整合，NXP、STMicro 与 Nvidia 的动作都指向边缘推理与本地化算力。对路由器读者而言，若计划在 25.12 上使用新工具链，建议先跟进 GCC 14.4.0 的合入进度再决定编译策略。
